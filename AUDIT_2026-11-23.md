# APLite — full pass audit & completion report (2026-11-23)

Scope: every Swift / ObjC source, project config, tests, scripts, CI and docs in the repository.
Method: full static source review (the Linux container has **no Xcode / Swift / UIKit**, so no local
build or on-device claim is made — CI remains the source of truth). Three focused sub-audits covered
cookie/account persistence, browser tabs / built-in web apps and the input/keyboard stack, followed
by a line-by-line review and a structural (balanced tokens / strings) check of every edited file.

## 1. Findings that were real bugs

| # | Finding | Fix |
| --- | --- | --- |
| 1 | Logins made in a web window on the external display were never copied into the local account vault. The only automatic save was `GoogleSession.save()` on the **phone** scene's `sceneDidEnterBackground`, filtered to Google domains. No `WKHTTPCookieStoreObserver` existed anywhere. | New `AccountCookies` observes the shared `WKWebsiteDataStore.default().httpCookieStore`, debounces a sign-in burst, saves known-site + auth-named cookies to the vault, and flushes on background, display disconnect and shutdown. |
| 2 | `CookieVault.save()` returned only *newly added* cookies. Re-saving a refreshed token returned 0, so Settings showed "No Google account is signed in" although the save succeeded. | Returns the number of cookies written (new **or** refreshed). Manual current-domain save has a correct message and a "Save all accounts" action. |
| 3 | Vault writes could race (WebKit callback queue vs. desktop Settings actions) and old files dropped `HttpOnly` / `SameSite`. | `NSLock`-serialised load/merge/write, atomic writes, backward-compatible decoding, and preserved cookie attributes on restore. |
| 4 | Find-in-page state was per-window, not per-tab: switching or closing a tab left stale highlights and counts. | `DeskWindow.selectTab` / `closeTab` clear the find bar; closing a background tab no longer clears an unrelated address draft. |
| 5 | Undo of a closed tab (`⌘⇧T`) always appended it at the end. `Close other tabs` bypassed undo entirely. Closed discarded tabs leaked their saved URL/title. | `Closed.tab` carries its original index, `DeskWindow.insertTab` restores it, "Close other tabs" records each tab, and `discarded` entries are purged on close. |
| 6 | History titles were patched only on `history[0]`; a late `<title>` callback after another navigation wrote to the wrong entry, and A→B→A within 30 minutes duplicated a row. | `updateTitle` finds the entry by URL, and `record` promotes an existing recent visit. |
| 7 | Web-app windows showed a generic globe/favicon and the page `<title>` in the dock and switcher instead of their branded icon and installed name. | `DeskWindow.icon` / `tabTitleChanged` prefer the installed `WebApps` entry for web apps. |
| 8 | `Layout.newTabRect(count: 0)` computed a rect from tab `-1`. | Explicit starting position when a browser window has no tabs. |
| 9 | `detachAll` removed only four of six registered script message handlers. | `WebAudioBridge` and the new focus bridge are removed consistently. |
| 10 | "Cookies from Safari" / "No cookies were found in what you pasted" mislabelled cookies that were never from Safari nor pasted. | Correct labels and messages in both settings surfaces. |

## 2. Features completed (not just stubbed)

### On-screen keyboard for the desktop
- `KeyboardLayout.swift`: pure, unit-tested layout with four rows of letters/numbers/symbols plus a
  function row. Every key APLite can forward is present: Esc, Tab, Caps Lock, both Shifts, Backspace,
  Enter, arrows, Home/End, PgUp/PgDn, Delete, Ctrl/Alt/⌘, Space, Select all / Copy / Paste, a 123
  symbol layer and a **hide** key.
- `WebInputFocusBridge.swift`: adds a `focusin`/`focusout` bridge to **every** tab (generalising the
  Files-only hook) and also queries `document.activeElement` after each synthetic click, so the
  keyboard shows only when an input actually has focus. Native fields, the address/find bars,
  sticky notes, Spotlight, the launcher and guest apps are covered by `DesktopModel.textInputActive`.
- `VirtualKeyboardView.swift` + `DesktopView`: standard floating-glass panel, hover highlight driven
  by the synthetic cursor, keycaps matching the existing desktop style, slide-in transition.
  Hit testing is in `DesktopModel.click()` because the external display's scene receives no touches —
  SwiftUI button taps there would be dead. Pressing a key routes through the same `typeText` /
  `backspace` / `pressEnter` / `sendKey` / copy-paste methods the iPhone and hardware keyboards use.
- Hide: the × key, Esc, or the next field after a hide brings it back. An "always visible" option
  exists for kiosk/TV use but is off by default.
- Settings: native System settings → Input has the on/off switch and a full **Keyboard settings &
  all keys** page (key map, size, click feedback); desktop Settings → Typing has matching toggles.

### Clean Facebook web app
- `FacebookEnhancements.swift` injects CSS/JS **only on facebook.com hosts**: rounded feed cards,
  glassy sticky header, hidden side/chat rails on narrow windows, styled scrollbars and marking of
  obvious sponsored units. It re-inserts its stylesheet if Facebook's React tree drops it, and can
  be toggled live from Browser settings. No APLite page and no other website is affected.

### UI/UX consistency
- New panels reuse `.floatingPanel` / `APLiteAnimation`; tabs now show site icons and a compact letter
  when too narrow to read; all new user-facing strings are in the Vietnamese string catalog.
- Version 1.2.6 in `project.yml`, the in-app changelog, README and live manifest.
