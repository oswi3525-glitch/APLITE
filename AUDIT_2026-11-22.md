# APLite — full repository audit & fix report (2026-11-22)

Scope: all 169 files / 92 Swift sources (~22.3k lines), build config, scripts, CI workflows and docs.
Method: static source review (this Linux container has no Xcode/Swift, so **no build or on-device
claim is made**). The Guest Engine (`Guest/*.m`, Mach-O patching, code signing) was reviewed but
left byte-for-byte unchanged to preserve compatibility.

## 1. Repository state before this pass

- Branding was APLite in the UI, but the source folder, bridging header and several docs still said
  `iDesk` — confusing for contributors and for the generated Xcode project.
- Zalo / Facebook / Telegram presets existed but only appeared after the user found a button deep in
  Settings; their icons were generic SF Symbols, not brand marks.
- Clocks were digital everywhere (desktop widget, quick panel, lock screen, screen saver).
- Only one bundled photo wallpaper ("Đồng cỏ"); no "Biển".
- Several genuine correctness/performance issues (list below).

## 2. Changes made

### Rename `iDesk/` → `APLite/`
- `git mv iDesk APLite`, `iDesk-Bridging-Header.h` → `APLite-Bridging-Header.h`.
- `project.yml`: `sources`, bridging header path, `Info.plist` path and all test-target source paths.
- Asset generator scripts, docs, issue template. Legacy `-iDeskPreview`, `-iDeskInstall`, `-iDeskOpen`
  arguments, `iDesk.*` UserDefaults keys, bundle id `com.hieuk.idesk`, guest bundle prefixes and the
  upstream attribution are **deliberately unchanged** so upgrades keep settings and guest apps.

### Apps
- `BuiltInWebApps` now installs Zalo, Facebook, Telegram, Chrome, YouTube and Gmail with bundled
  branded PNG icons at first launch; Settings → Applications can re-add them any time.
- These are web shortcuts; native apps still require a decrypted IPA (unchanged policy).

### Assets & wallpapers
- All raster assets regenerated deterministically (`scripts/generate_assets.py`): app icon, launch
  mark, lock mark, Browser/Files/Settings/Trash icons plus new Zalo/Facebook/Telegram icons.
- New `scripts/generate_ocean.py` produces the 1920×1080 "Biển" wallpaper next to "Đồng cỏ".
  Both are selectable from desktop Settings (now with **real image thumbnails**) and the native
  System settings sheet; `nextWallpaper()` cycles photos → gradients → dynamic without gaps.

### Analogue clock
- New reusable `AnalogClockView` (drawn face, ticks, hour/minute/second hands) used by the desktop
  widget, quick panel, lock screen and screen saver. Digital time remains as a readable companion.

### Performance & correctness fixes (audit findings)
| # | Finding | Action |
| --- | --- | --- |
| 1 | Sticky notes saved synchronously on every drag event | Debounced 0.4 s + flush on background |
| 2 | `favicons` cache grew forever; unbounded favicon download size | 100-entry cap, 2 MB decode limit |
| 3 | `gamePages` identifiers never removed on tab close | Bound at 100 + drop stale IDs |
| 4 | `fillThumbnails` (6 window-sized images) leaked on most dismiss paths | Cleared in `fillSuggestion.didSet` |
| 5 | `WebApps.icons` / Settings base64 icon caches unbounded | 64-entry caps; icons preloaded at init |
| 6 | Session restore ran before the external display connected, then discarded the session | Deferred until display connects and retried |
| 7 | `PageZoom.apply` added a `DOMContentLoaded` listener on every navigation | Registered once per document with `{ once: true }` |
| 8 | Lock screen's 1 s tick re-evaluated and re-blurred the whole wallpaper | Clock isolated in its own `LockClockView` |
| 9 | All widgets redrawn every second by one shared timer | Per-widget cadence: clock/timer 1 s, others 30 s |
| 10 | Screen saver ignored Performance mode; CacheManager reported success early | Honours `performance`; reports only on WebKit completion |
| 11 | 40 MB file drop read synchronously on main thread | Stat first, read/decode in background |
| 12 | Quick Look decoded a photo inside SwiftUI `body` | Preload off main thread when selection changes |
| 13 | Folder sizes recomputed every 5 % of a download | Throttled to every 20 % |
| 14 | Download history (`resumeData`) grew without bound | Trim to 50 finished items |
| 15 | `nextWallpaper` desynced when a live manifest shrank the palette list | Uses the actual displayed count |
| 16 | Sticky `CADisplayLink` keep-alive, un-invalidated audio/thermal timers, MPRemoteCommand tokens | Invalidated in `deinit`; media-command tokens removed from their owning `MPRemoteCommand` on re-start |
| 17 | Mouse diagnostics list rebuilt 4×/s | 1 s cadence |
| 18 | `lastTrim` set twice in CacheManager | Single assignment on completion |

### UI/UX
- Real wallpaper thumbnails instead of emoji tiles in Settings; wallpaper controls added to the
  native iPhone settings sheet; branded app icons on the desktop/dock; changelog and live manifest
  updated for 1.2.5.

## 3. Reviewer notes / consciously not changed
- Guest Engine files are untouched (audit doc: compatibility must be preserved).
- Full-screen `drawHierarchy` capture in RemoteDisplay / ScreenRecorder stays on the main thread:
  UIKit view hierarchy rendering is main-thread-only; removing it would require a different capture
  technology (ReplayKit), out of scope for this pass.
- Screenshot PNG encoding is still synchronous at capture time (user-initiated, one-off).
- `MouseInput` counters and `TaskbarView` hover state inherently re-evaluate on pointer movement;
  layout math was de-duplicated previously and is cheap for normal window counts.
- Historical upstream document `README.vi.md` and attribution files keep the original iDesk wording.

## 4. Verification status
- Static review of all edits: no compile errors found (second pass included).
- Python asset generators were executed successfully; new PNGs committed.
- **Not verified:** Xcode build, unit tests and on-device behaviour — this environment has no
